# 23 把人类审批放进状态机

[上一课](22-notifications.md) · [学习路线](../README.md) · [下一课](24-digital-employee.md)

## 人的回复也是一项任务输入

“等待人确认”不是流程之外的空白。系统必须保存问了什么、问谁、针对哪份东西，以及有效答案将让任务走向哪里。

例如工单 1042 已准备好补丁，接下来准备创建一个 PR。审批对象应是具体动作和候选版本，而不只是全局 `approved=true`。

```json
{
  "request_id": "approval-demo-1042-2",
  "action": "create_draft_pr",
  "target": "demo-repository",
  "candidate_digest": "computed-digest-of-current-candidate",
  "decision": "pending"
}
```

这是教学数据。实际系统应从可信执行端计算摘要，并在接收回复时验证身份和字段，而不是信任模型或客户端随便填的值。

## 测试通过和授权通过不能互相替代

测试者说“功能看起来正确”，表达质量判断。仓库负责人说“可以合并”，表达操作授权。这两个人可以是同一个人，但两种结论仍然不同。

同样，用户批准创建 PR，不必然批准合并；批准合并，不必然批准部署生产。请求里要写明要做的具体动作及后果。

## 人批准 A 之后产物变成 B

这时不能直接沿用旧批准。程序应重新比较当前候选版本与批准绑定的版本，按策略重新验证或重新申请。

只在审批入口检查一次还不够。实际动作执行前也要检查，避免等待期间发生变化。在可能并发更新的远端，还应使用服务提供的版本条件或保护机制，不能把“刚查过”当成永远不变。

## 框架帮助暂停 业务负责验证

LangGraph 的 interrupt 和 OpenAI Agents SDK 的人工审批运行状态都能帮助表达暂停与恢复，但应用仍需认证回复者、校验审批内容、保存有效范围。[LangGraph 中断](https://docs.langchain.com/oss/python/langgraph/interrupts)、[Agents SDK 人工参与](https://openai.github.io/openai-agents-python/human_in_the_loop/)

在公开底盘的当前源码中，可以找到同步人类回调，但不能据此声称已有跨重启、身份认证、产物绑定的完整审批系统。后者在本教程中属于设计建议。[源码证据范围](../references/sources.md#r06)

## 拒绝和取消也要能正常结束

拒绝审批不是模型应该设法绕过的障碍。它可能意味着返工、缩小范围或结束任务。取消任务后应阻止尚未执行的动作，同时诚实记录已经发生且不能撤销的外部影响。

## 小练习

审批回复晚到一天，此时任务已经取消。你的系统应该恢复发布吗？写出拒绝这个旧回复所需的状态检查。

**带走一句话：有效审批必须对应正确的人 动作 目标和版本。**
