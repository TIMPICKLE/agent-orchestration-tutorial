## 没有人发消息时 Agent 怎样开始工作

常见触发有三类：收到 webhook、到达定时时间、子任务状态改变。外部程序收到这些事件后，再决定是否启动或恢复一次 Agent 运行。

模型不是在两次调用之间持续思考。所谓“它主动继续做了”，通常意味着某个调度器或常驻进程在适当时机给了它新的输入。

```text
事件发生 → 验证来源 → 保存事件 → 选择任务 → 唤醒运行
                                              ↓
                            模型决定动作 → 工具执行 → 保存结果
```

## 送达 唤醒 执行 成功

事件送达：入口收到了它。

唤醒运行：调度器启动或恢复了某次执行。

动作执行：某个工具真正开始工作。

任务成功：目标产物及验收证据满足要求。

这四个节点不能省成一句“Agent 收到任务了，所以已经做了”。一个服务返回 HTTP 200，可能只表示事件已接收；一个队列确认可能只表示消息已消费。都需要看协议具体承诺。

## 一个源码可见的唤醒例子

Multica 把 Agent 的长期身份与一次具体 Run 分开。任务分配或结构化 mention 可以让平台创建一轮执行；后台 daemon 领取任务后调用编码运行时。[固定版本触发与运行资料](../references/sources.md#p05)

它的 Agent 没有人类式 inbox。人类 inbox 通知与 Agent 执行触发是两条路径。不能把“被 @”理解成 Agent 收到一封邮件后持续等待；平台会按规则决定是否入队运行。

在 Squad 协作里，leader 可以委派后结束本轮；成员结果或相关事件再触发新一轮 leader。常驻的是身份与任务关系，不要求模型进程一直运行。完整例子见 [Multica 短案例](../cases/04-multica.md)。

## 异步子任务为什么需要任务标识

同步调用会等待结果；异步调用通常先返回任务 ID，稍后查询或接收完成事件。主任务要保存这个 ID，才知道结果属于谁。

Deep Agents 当前文档提供异步子 Agent 的 start、check、update、cancel、list 工具。它们建立了后台任务生命周期，但文档中的这些接口本身不保证完成时自动唤醒主管。[异步子 Agent 文档](https://docs.langchain.com/oss/python/deepagents/async-subagents)

这种异步子任务需要配套 Agent Protocol 兼容服务和对应 graph 部署。仅调用一个普通 async 函数，或创建一个本地 `create_deep_agent` 对象，不会自动获得持久后台执行。

因此，你还应检查部署是否提供完成事件，以及由谁消费、恢复哪个主任务。不要把“后台能运行”误当作“结果会主动找到人”。

## 小练习

设计工单 1042 的 CI 完成事件：保存哪个 build ID？它对应哪份代码？旧构建的结果到达时是否应该唤醒当前流程？

**带走一句话：主动性来自触发与调度，模型负责被唤醒之后的判断。**
