# 27 控制成本 权限与上下文

[上一课](26-evaluation.md) · [学习路线](../README.md) · [下一课](28-frameworks.md)

## 长时间工作需要资源边界

系统可以自主继续，不代表可以无限调用模型、无限读取资料或永远重试。预算让系统在价值不足时停止，并把当前结果交还给人。

至少区分三类限制：任务总运行时间、动作或模型调用数量、允许使用的资源与外部目标。真实系统还可能增加 token 和费用上限。

不同限制解决不同问题。只限制循环次数，单次工具仍可能耗时很久；只设置超时，恢复后不断重试仍可能花很多钱。

## 上下文也是资源

把所有日志和聊天不断追加给模型，会使成本上升，也会让重要事实更难被找到。

可以把上下文分成：当前目标和约束、当前可信状态、相关证据摘要、按需读取的原始产物。每次只提供当前决定需要的内容。

摘要必须保留不确定性和来源。不要把“可能是格式问题”压缩成“已确认格式错误”，也不要在传递时丢掉候选版本。

## 共享发现需要更正机制

一个 Agent 先发出结论 A，后来证据推翻它得到 B。如果别的 Agent 仍拿着 A 继续工作，团队会分裂成不同的现实。

因此共享知识除了新增，还要能标记替代、冲突和更正。公开项目 `mu` 的 hive 代码展示了发现关系与有选择的投递机制，可用于研究这个局部问题。[固定版本源码入口](../references/sources.md#p04)

这类相关性筛选会减少上下文占用，但也可能漏掉关键消息。你仍需评估漏发率与误发率，不能只衡量节省了多少 token。

## 上下文隔离不等于安全隔离

给两个 Agent 各自一段对话，能够降低相互干扰。如果它们仍共用同一个高权限 shell 或凭据，它们依旧可能修改相同资源。

同样，git worktree 是不同工作副本，不是操作系统沙箱。它帮助分离代码修改，不能单独限制网络、目录访问和凭据使用。

公开底盘的权限 wrapper、Deep Agents 的文件能力以及其他 harness 都需要逐条检查执行边界；不能根据一个产品名称推断所有工具受到相同控制。[底盘权限路径](../references/sources.md#r03)、[Deep Agents 子代理](https://docs.langchain.com/oss/python/deepagents/subagents)

## 小练习

你的 reviewer 只能看 diff，却能调用任意 shell。它真的是只读角色吗？列出真正限制它写入所需的执行端措施。

**带走一句话：上下文限制帮助思考，权限限制约束行动，预算限制控制代价。**
