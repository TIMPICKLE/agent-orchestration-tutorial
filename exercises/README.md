# 综合练习

[学习路线](../README.md) · [逐课答案](../lessons/32-solutions.md) · [离线实验](../examples/README.md)

练习分为解释、画图、运行和故障分析。建议每次只做一关，保存自己的答案。标准不是用了多少框架，而是能否解释选择、保留证据和正确处理失败。

## 第一关 读懂一个工具调用

画出：工具说明交给模型 → 模型选择工具和参数 → 运行时校验 → 真正执行 → 结果回传 → 下一次决策。

再分别说明这三个情况：模型只说“我要测试”；模型请求了未知工具；工具实际完成但结果没返回模型。

**验收：** 能够区分意图、工具请求和真实动作。未知工具不会凭空获得执行权限。

## 第二关 运行固定流程

按 [示例指南](../examples/README.md) 运行 `examples.fixed_workflow`。解释为什么原始解析器失败，为什么简单去逗号仍不能通过全部测试。

**验收：** 指出目标样例成功并不足够；非法格式也需要被拒绝。不要把候选函数预先写好误认为运行时模型自动生成了代码。

## 第三关 观察有界循环

运行 `examples.bounded_loop`，追踪五个动作。然后阅读预算耗尽测试，解释“动作步数”和“修复次数”的区别。

**验收：** 能够指出哪一步产生测试证据，哪些状态改变会使证据失效，以及为何假模型不代表真实自适应推理。

## 第四关 画图但先不装新框架

把同一过程画成节点和条件边。只要保留状态和判断规则，先用纸就可以。

再阅读 [完整 LangGraph 装配示例](../framework_samples/langgraph_complete.py)，对照每个节点。该文件是未执行框架集成的示意，运行要求见其 [说明](../framework_samples/README.md)。

**验收：** 状态、函数和路由能一一对应。能解释图没有让原来的假模型突然更聪明。

## 第五关 模拟消息响应丢失

运行 `examples.message_delivery`，找到外部效果发生、本地确认保存、恢复对账这三个时刻。

**验收：** 同一消息重试复用稳定 ID；相同 ID 携带不同内容被拒绝；知道这个假服务为什么能支持对账，也知道不能推断所有真实服务都支持。

## 第六关 让旧批准失效

运行 `examples.approval_resume`，观察待审批、批准与拒绝旧批准的路径。

**验收：** 能够说出至少四种需要使旧批准失效的变化，例如任务、动作、目标、候选版本改变。区分文件恢复演示与真实用户认证。

## 第七关 设计一个专家

为金额解析任务增加一个只读审查者。写出输入、输出、权限和停止条件，再决定使用工具式调用还是 handoff。

**验收：** 能解释谁在审查后继续负责；不把专家一句 PASS 当作完整测试证据；提出一个判断专家是否有价值的对照实验。

## 第八关 设计完整人机工作流

填写 [工作表](../design/worksheet.md)。任务可以选择“工单到本地补丁”或“工单到待审核 PR”，必须明确停止点。

注入三个故障：重复工单事件、发布结果未知、任务取消后批准才到。

**验收：** 每个故障都有明确状态、证据和下一步；不依赖模型凭记忆猜测外部事实；不扩展用户授权。

## 参考解法

1. **工具机制：** 模型产出请求不等于执行；运行时应拒绝非法调用并反馈原因。
2. **固定流程：** 合法 `1,234.50` 应通过，非法 `12,34.50` 仍应拒绝；应在规范化前验证格式。
3. **循环：** 脚本化假模型用于观察协议，真正模型还需要独立评估；预算按实际计量对象命名。
4. **图：** 节点负责工作，条件边按测试与预算路由；持久化不是画出环后自动获得。
5. **消息：** 稳定意图 ID 与接收端支持共同提供去重；结果未知先对账。
6. **审批：** 执行前重验授权与当前目标，不能用裸布尔值批准任何后续版本。
7. **专家：** 有限子任务通常适合工具式调用；需要继续负责对话时才考虑 handoff。
8. **全流程：** 每个阶段的质量证据、动作权限、等待事件及负责人都能明确指出。

这些是推理方向，不是强制唯一实现。若你的答案不同，说明适用条件和测试方式即可。
